## 1. Purpose of this document

This page gives readers context: where this small, transparent workbench sits relative
to the broader field of deep learning in biology, and what might reasonably be added
later. It is **not** a literature review. It makes no claims about the results of any
published work.

## 2. What this project is

This workbench is an **independent implementation**. Everything here was written for
this repository:

- a seeded synthetic data generator with a planted, known answer
- validation and quality control
- a transparent two-group comparison: Welch t-test, Cohen's d, and Benjamini-Hochberg
  adjustment
- a documented ranking heuristic
- one leakage-safe logistic-regression baseline

All of it is verified against the planted ground truth. The project deliberately uses
**no deep learning**. See [`methodology.md`](methodology.md),
[`architecture.md`](architecture.md), and
[`limitations_and_ethics.md`](limitations_and_ethics.md).

## 4. Where this project sits relative to that landscape

Deep-learning methods in biology generally depend on large real datasets and careful,
independent validation. This workbench has neither by design. It has 80 simulated
samples, and its goal is to make every step inspectable and checkable against a known
planted answer. For that teaching goal, classical statistics and a simple baseline
classifier are the appropriate tools.

This project makes **no claim** of comparability, equivalence, or competitiveness with
any deep-learning work, including anything in the index above.

## 5. Why deep learning is not used today

- **Sample size:** 80 synthetic samples are far too few to justify high-capacity models.
- **Data:** the synthetic groups are separated by large planted effects that simple
  methods already recover by construction. A complex model would teach nothing extra and
  could invite overinterpretation.
- **Interpretability:** auditable, hand-checkable statistics are a core goal.
- **Evaluation discipline:** the existing leakage-safe baseline, with a permuted-label
  sanity check, is the foundation any future model would have to respect.
- **Footprint:** the project avoids heavy dependencies and pretrained artifacts.

## 6. Future extensions (not implemented)

> **Status: NOT IMPLEMENTED. Documentation only.** Phase 6A added no code,
> dependencies, data, models, or weights.

### Possible future module: synthetic transcriptomics autoencoder (educational)

- **Goal:** teach how a small nonlinear model compresses the 500-gene synthetic matrix.
  It would compare the model's low-dimensional view with the existing PCA on the known
  planted structure. This would be a visual teaching comparison, **not** a performance
  benchmark.
- **Data:** **only** this repository's synthetic generator output. No patient data, no
  real clinical data, and no external or unverified datasets of any kind.
- **Models:** trained from scratch on synthetic data only. No pretrained biological
  models and no external or downloaded model weights. No weights would be committed or
  written by default.
- **Dependencies:** it would prefer tools already in the stack; for example,
  scikit-learn's `MLPRegressor` can act as a tiny autoencoder. Any deep-learning framework
  would need separate approval, and would go in a pinned optional extra, never in the
  core requirements.
- **Guardrails, if ever approved:**
  - leakage-safe train/test handling, with preprocessing inside a fitted pipeline
  - a fixed seed and determinism tests
  - DEMONSTRATION / SYNTHETIC labels on every output
  - nonclinical wording and its own limitations section
  - kept separate from `obw run-analysis`
- **Out of scope, even in the future:** clinical prediction, cancer classification,
  biomarker discovery or validation, and any claim of biological or real-world validity.

No other roadmap items are proposed. Any further extension would need a new, separately
approved planning phase.
